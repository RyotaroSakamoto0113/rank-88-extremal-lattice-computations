# 独立した D4 shard 証明書の検算

実行例:

```sh
python3 verify_d4_shard.py /absolute/path/to/completed/shard --gp /opt/homebrew/bin/gp
```

既定の出力先は shard 内の新しい `independent_certificate/`。既存の出力先には上書きしない。`--output`、`--lookup`、`--exact-counts` で別の出力先、通常短ベクトルの軌道表、独立列挙結果を指定できる。

この検算器は production の `common.gp`、`d4.gp`、枝刈り関数をロードしない。GP の基本的な整数行列演算を利用し、以下を再構成する。

1. すべての整数商形式について、保存した prefix と cusp 基底、整数補空間から各行列成分を作り直す。prefix Gram の行列式を Bareiss 法、逆行列の分子を余因子で求め、Schur complement を照合する。
2. ねじった整数核は、(y=Rt/2\in\mathfrak a^{-1}R) の条件を (omega t\equiv0\pmod2) または ((omega-1)t\equiv0\pmod2) に変換して構成する。合同条件の整数核、法2の階数、指数を検査し、保存した補空間との結合行列が unimodular であることを確認する。
3. 保存された各商ベクトルが非零、整数、範囲内で、符号対として重複しないことを確認する。各ベクトルから元の22次元座標の拡張を作り、trace Gram の Bareiss 行列式から (delta) を確認する。
4. 全 raw ベクトルは、保持または一つの棄却記録にちょうど一度だけ対応しなければならない。棄却理由は非飽和、通常の短ベクトル、既存の同値部分格子、先行する第二部分格子の四種をそれぞれ検算する。
5. 通常短ベクトルの証人は (Rz=v)、元の Gram によるノルム、完全な参照球の軌道ID、第一方向より先の順序を確認する。
6. 二次部分格子の重複は第一方向の安定化群の全像から canonical な実部分格子を作って比較する。三次の重複は、以前に保持したものと整数部分格子そのものが等しいことを確認する。
7. 第二方向の順序による棄却は、実際の (R'\subset T) を再構成し、(P\subset R')、正しい行列式、より小さい行列式または同じ行列式でのより先の canonical 順序を検算する。同じ行列式の場合は飽和性も必要とする。
8. 初期の rank1 Steinitz 類は別の初期データ検算を前提とし、その後の類の加算、各段階の切断値、保持した候補から必要な全イデアル類の形式が生成されていることを確認する。

最終的な完全性には、別実装の整数・GMP列挙器の結果が必要である。`exact_enumeration.stdout` の全形式について `complete=true`、形式ID、次元、上限、符号付きベクトル数を照合する。保存されたベクトルがすべて妥当で重複せず、その数が独立した完全列挙の数と一致するため、保存された各球が完全であることが従う。空のGP出力だけを根拠に完全性を認めることはない。

`coverage.csv` に各 raw ベクトルとその処理を記録する。`verification.json` には入力・コードのハッシュ、全個数、工程の実時間・user CPU・system CPU・開始終了時刻を記録する。入力の既存ファイルは変更しない。

PARI の内部並列処理に関する実環境の停止を避けるため、検算用プロセスには最初に `default(nbthreads,1)` を設定する。これは演算結果や数学的範囲を変更しない。
